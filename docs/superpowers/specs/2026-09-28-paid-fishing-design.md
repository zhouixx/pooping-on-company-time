# 带薪摸鱼前端设计规格

## 1. 目标

构建一个可爱、可直接使用的单页前端工具，让用户按自己的工作节奏计算本月工作日、税前时薪，并通过计时器实时看到本次摸鱼收益。

第一版面向中国大陆工作日规则，支持单休、双休和大小周，读取外部节假日/调休接口，接口异常时回退到本地数据。

## 2. 已确认的产品规则

- 单休：周日休息，周六上班。
- 双休：周六、周日休息。
- 大小周：用户选择当前周是单休周还是双休周，之后按自然周交替。
- 工资输入口径为税前月薪。
- 每天上班小时数参与工作总工时和时薪计算。
- 时薪公式：`税前月薪 ÷ 本月工作日 ÷ 每天上班小时数`。
- 摸鱼收益按用户选择的结算单位计算：按秒为 `完整秒数 × 时薪 ÷ 3600`，按分钟为 `完整分钟数 × 时薪 ÷ 60`，按小时为 `完整小时数 × 时薪`。默认按分钟，例如摸鱼 1 分钟，收益就是 `时薪 ÷ 60`。
- 非工作日（周末、法定假日或休息日）不允许启动计时器，提示“今天不用上班，安心休息”。
- 计时器支持开始、暂停、继续、结束本次和重置；刷新页面或关闭后恢复计时状态。
- API 优先；请求失败时使用本地回退数据，并显示当前数据来源。
- 当前演示月份为 2026 年 9 月，示例应覆盖 9 月 20 日调休上班、9 月 25 日中秋节、9 月 26/27 日周末休息，并计算出 22 个实际工作日。

## 3. 页面结构

页面采用单列流程，顺序固定为：

1. **品牌区**：标题「带薪摸鱼」、可爱摸鱼小动物插画、月份选择、API/本地数据状态。
2. **工作节奏**：单休、双休、大小周三个分段选项；大小周额外出现当前周类型选择。
3. **薪资设置**：税前月薪、每天上班小时数。
4. **月度结果**：工作日数、总工时、时薪和休息/调休摘要。
5. **月历**：展示当月每一天的工作状态、节日名称、调休说明和数据来源；支持手动修正日期。
6. **摸鱼计时器**：提供按秒、按分钟、按小时的结算单位选择（默认按分钟），按所选单位显示当前有效摸鱼时长和本次收益；非工作日禁用开始按钮。

桌面端限制内容宽度并居中，移动端保持同样的流程顺序，触控目标不小于 44px。

## 4. 视觉方向

整体采用“办公桌上的可爱贴纸”风格：暖米白背景，珊瑚橙主色，薄荷绿、天空蓝和柠檬黄作为状态色，正文使用深炭色和清晰的中文系统字体。页面使用一张小型可爱摸鱼插画作为第一视觉，不使用大面积渐变或装饰性圆形背景。

状态色语义固定：

- 珊瑚橙：调休上班日或主要行动按钮；
- 薄荷绿：普通休息日；
- 浅蓝：法定节假日；
- 米灰：普通工作日或未设置状态。

按钮和输入控件使用紧凑圆角（不超过 8px），图标只辅助含义，不替代关键文字。计时器在运行、暂停、结束和不可用状态下都有明确的文字和颜色反馈。

## 5. 技术架构

采用 React + Vite 单页应用，不引入后端代理。代码按职责拆成以下模块：

- `calendar adapter`：请求公开节假日 API，将提供方响应转换为统一日期记录；处理超时、错误和格式异常。
- `workday calculator`：根据工作节奏生成基础工作日，再按节假日、调休和本地修正覆盖。
- `salary calculator`：根据工作日数、月薪和每日工时计算总工时及时薪，负责输入校验。
- `timer state`：用时间戳和累计毫秒数管理计时器，负责开始、暂停、继续、结束、重置以及持久化恢复。
- `components`：页面流程、设置控件、月历、结果摘要和计时器的展示层。

推荐的公开接口为无需 Key 的年度节假日接口（例如 `timor.tech` 年度接口）。具体提供方响应只在 adapter 内处理，组件不依赖外部数据结构。

## 6. 数据模型

```ts
type WorkPattern = 'single' | 'double' | 'alternate';
type WeekType = 'single' | 'double';
type DayStatus = 'work' | 'rest' | 'holiday' | 'makeup';

interface Settings {
  month: string; // YYYY-MM
  salary: number;
  hoursPerDay: number;
  pattern: WorkPattern;
  alternateWeekType: WeekType;
  settlementUnit: 'second' | 'minute' | 'hour';
  overrides: Record<string, DayStatus | null>;
}

interface CalendarDay {
  date: string; // YYYY-MM-DD
  weekday: number;
  status: DayStatus;
  label?: string;
  source: 'pattern' | 'api' | 'local-fallback' | 'user';
}

interface TimerState {
  status: 'idle' | 'running' | 'paused' | 'finished';
  accumulatedMs: number;
  startedAt: number | null;
  lastUpdatedAt: number | null;
}
```

## 7. 日期计算与数据流

1. 根据月份生成完整日期列表，并确定每个日期的自然周。
2. 按 `single`、`double` 或 `alternate` 生成基础工作/休息状态。大小周的当前周类型由用户选择，后续自然周交替。
3. 将 API 返回的法定节假日和调休工作日覆盖基础状态。
4. 应用 `Settings.overrides` 中的用户修正；非空修正拥有最高优先级。
5. 汇总 `status === 'work' || status === 'makeup'` 的工作日数，计算总工时和时薪。
6. 当前日期若不是工作日，计时器不允许从 `idle` 开始；若已存在运行状态且跨到休息日，计时器在当天刷新时暂停并提示原因。
7. 计时器内部以毫秒记录经过时间，但收益只按所选单位的完整数量结算。按秒使用 `floor(elapsedMs / 1000) × hourlyRate ÷ 3600`，按分钟使用 `floor(elapsedMs / 60000) × hourlyRate ÷ 60`，按小时使用 `floor(elapsedMs / 3600000) × hourlyRate`。页面显示跟随所选单位，不混合展示其他单位。

API 状态分为 `loading`、`success`、`fallback` 和 `error`。超时或解析失败时切换到本地回退数据，保留基础规则和可编辑修正，不阻塞页面使用。

## 8. 持久化

使用同一站点共享的 `localStorage` 保存；若存在多端口版本留下的同名 Cookie，首次加载时自动迁移后删除：

- 用户设置（月份、工作节奏、大小周当前周类型、月薪、每日工时）；
- 用户对日期的修正；
- 当前计时器状态。

恢复运行中的计时器时，以 `Date.now() - startedAt` 重新计算经过时间，避免依赖页面是否持续渲染；显示和收益取所选单位的完整数量。切换结算单位时保留同一段毫秒累计值，并按新单位重新计算展示和收益。结束本次只冻结状态和收益，点击重置才清零。

## 9. 异常处理与可用性

- 月薪和每日工时必须为大于 0 的数字，输入不合法时阻止收益计算并显示字段级错误。
- API 请求设置超时；网络不可用、HTTP 错误或字段缺失都进入回退状态。
- 回退数据仅代表当前演示月或已知日期；页面明确标注“本地数据”，避免把示例当作实时结果。
- 日期详情显示节日名称、调休说明和来源，便于用户发现数据问题。
- 结算单位切换使用分段控件，切换时不重置计时器；当前单位和收益公式始终可见。
- 所有核心按钮支持键盘聚焦，颜色状态同时配合文字标签，不依赖颜色单独传达含义。

## 10. 测试计划

使用项目配置的测试工具覆盖以下行为：

- 单休、双休和大小周在月初/月末及跨月时的工作日计算；
- 大小周当前周类型切换后的交替结果；
- 法定假日覆盖普通工作日、调休周末恢复上班；
- 2026 年 9 月示例得到 22 个实际工作日；
- 月薪、每日工时校验和时薪精度；
- 计时器开始、暂停、继续、结束、刷新恢复和重置；
- 秒、分钟、小时三种结算单位的换算、切换和默认值；
- 按分钟计时 1 分钟时收益等于 `时薪 ÷ 60`，各单位未满一个完整单位时不计入已结算收益，页面按所选单位显示；
- 非工作日禁止开始计时；
- API 成功、超时、异常响应和本地回退；
- 本地日期修正覆盖 API 与基础周规则；
- 主要移动端宽度下布局不溢出，按钮与日历可操作。

## 11. 明确不包含的范围

- 不做个税、社保、公积金或实际到手工资计算；
- 不接入账号、云同步或服务端数据库；
- 不做长期历史摸鱼报表，只保留当前计时会话和当天累计收益；
- 不保证第三方节假日 API 永久可用，回退数据和来源提示是必要组成部分。

## 12. 多端口互动流程（历史方案，已由第 13 节取代）

页面拆成五个可独立打开的步骤，开发环境端口与步骤固定映射：

- `5173`：01 工作节奏；
- `5174`：02 薪资设置；
- `5175`：03 本月结果；
- `5176`：04 月历；
- `5177`：05 摸鱼计时器。

每个端口只渲染对应步骤，同时保留统一品牌头、步骤进度和上一步/下一步导航。导航使用当前主机名加目标端口，保证用户也可以通过 `127.0.0.1` 或其他本地主机名访问。应用仍使用同一个 Vite bundle，通过 `window.location.port` 选择步骤；`npm run dev:all` 启动五个端口。

由于浏览器 `localStorage` 按端口隔离，用户设置和计时器状态改用 `document.cookie`（`Path=/`、`SameSite=Lax`、一年有效期）跨端口共享；读取时兼容旧版 `localStorage` 并自动迁移。Cookie 仅保存小型 JSON 配置，不包含敏感信息。

计时器状态增加当天累计收益和收益日期。结束一次会话时，把本次收益按结束瞬间的时薪写入当天累计；运行中或暂停中的当前会话收益只在展示层临时相加。跨自然日读取状态时清空当天累计并重置旧会话，避免把前一天收益带入今天。点击“重置计时”只清当前会话，保留当天已结束会话累计。

## 13. 同域路径流程（公网部署增量）

本节取代第 12 节中的多端口访问与 Cookie 持久化方案，计时器的今日累计规则保持不变。

- 五个步骤改为同一域名和端口下的 `/01`、`/02`、`/03`、`/04`、`/05`。
- `/` 和未知路径兼容显示 01；页面中的正式步骤链接始终使用 `/01`～`/05`。
- 导航链接使用站内绝对路径，不写协议、主机名或端口，适配 localhost、Vercel 预览地址和自定义 HTTPS 域名。
- 同源路径共享 `localStorage`，设置和计时器状态从 Cookie 切换回 `localStorage`。
- 若浏览器存在上一版同名 Cookie，第一次加载时优先读取 Cookie，写入 `localStorage` 后删除旧 Cookie，避免丢失最新设置。
- 删除 `dev:all` 和五端口启动脚本，本地仅需 `npm run dev`；Vite 开发服务器负责将 `/01`～`/05` 回退到 `index.html`。
- 添加 Vercel SPA 重写配置，使公网直接访问或刷新 `/01`～`/05` 时仍返回应用入口。

## 14. 中性公开标题

- 页面主标题从“带薪摸鱼”改为更中性的“今日进度”，降低被旁人扫到时的辨识度。
- 浏览器标签页标题同步改为“今日进度”，避免标签栏暴露原名称。
- 保留 H1，不通过隐藏或删除标题破坏页面层级和无障碍结构。
- 项目内部名称、README 和功能文案保持不变，本次仅处理最醒目的公开标题。
